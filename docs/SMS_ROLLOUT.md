# Conversational SMS rollout

These changes are prepared for review. The job creates two PRs and leaves deployment, production settings, PM2 and Twilio configuration to Claude after review.

1. Review both PRs together. Apply the API PR's prepared SMS migration using the API database procedure, then verify its constraints and thread index before deploying API consumers. The migration is additive and preserves default home threads; it enables the SMS execution policy and separate SMS threads.
2. Build and deploy the reviewed API and its Primary worker with the same source. Confirm the authenticated `/internal/primary-dexter/channels/phone/sms/turns` route is installed and workers understand `sms_read_only`. Use a disposable account for integration checks.
3. Prepare the reviewed Teledexter immutable release with Node 22 or later. Run `nice -n 10 npm ci`, `nice -n 10 npm run typecheck`, `nice -n 10 npm test -- --test-concurrency=2` and `nice -n 10 npm run build` against that source. Retain the current broker journal and SMS ledger. Stop the prior broker before starting the successor against the same state; follow BROKER_OPERATIONS.md for PM2 and release handling.
4. Set these existing variables in the broker's production env file. `TWILIO_MESSAGING_SERVICE_SID` must be the `MG...` SID of the approved **Dexter SMS** service holding the registered number; obtain the actual SID from the Twilio console. `DEXTER_SMS_CAMPAIGN_APPROVED=true`. Set `DEXTER_SMS_ADVANCED_OPT_OUT_CONFIGURED=true` only after the keyword setup in step 5. Set `DEXTER_SMS_SEND_ENABLED=true` when ready to activate sends. No new environment variables are introduced. Verify `DEXTER_SMS_ENROLLMENT_ENABLED=true` so the signup link can complete enrollment. Existing durable state, internal proxy secret, Twilio credentials, destination number, public HTTPS origin, `DEXTER_API_URL` and `PHONE_SERVICE_SECRET` remain required. Webhook validation must remain enabled.
5. In Twilio, confirm the approved campaign and registered number belong to Dexter SMS. Enable Advanced Opt Out with the STOP/START/HELP words and responses documented in sms.md. Change that service's incoming webhook from the demo responder to `https://<broker-public-host>/sms/incoming`, method POST. The hostname must equal `DEXTER_PHONE_PUBLIC_URL`; mismatched public URLs fail signature validation. Delivery callbacks are supplied by the sender as `/sms/status/<message-id>`.
6. Start the reviewed broker with the final env and save PM2 state. Confirm `/broker/health`, signed webhook admission, internal SMS readiness, voice reception and a separate test account's conversation. Check signup-once, STOP silence, HELP/START handling, balance reply and a money request's passkey link. Confirm the financial action did not execute. Use an owned test number/account; keep Branch's phone thread out of tests.

SMS setup failure logs `service: sms, state: disabled` while voice remains available. Broker health alone does not prove texting works; inspect `/internal/sms/config` with the existing internal secret and the test account's carrier outcome. Pending API responses are polled at two-second intervals. Model and carrier latency have not been measured by local fake-provider tests.

For rollback, preserve the current SMS ledger, including signup markers and carrier reservations. The old reader rejects the new inbox states; use a compatible reader before re-enabling SMS. Keep the API's new thread column and execution policy while SMS runs or records remain. Follow the API PR's rollback notes. A rollback must preserve new send history rather than restore an older ledger snapshot.
